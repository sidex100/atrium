Потребление в простое — 3–4 Вт на процессоре. Температура в простое 45–55 °C, под полной нагрузкой
до 75 °C.

Важно: имена дисков `nvme0` и `nvme1` — это порядок обнаружения при загрузке, а **не** слот. Они меняются
от загрузки к загрузке. В системе диски адресуются по UUID, а в командах — по модели.

## BIOS

У нас стоит **ASER5012**. Заводской BIOS линейки 24 ГБ — ASER5009. Обновление делается **из Windows**,
которая стоит на боксе с завода, до установки Linux:

1. С сайта поддержки Beelink скачай архив BIOS для SER5 MAX (Ryzen 7 7735U). Файл `ASER5012.BIN` из
   папки SER5-MAX-7735 («Only Aser501X can flash») байт в байт совпадает с файлом из папки SER5-MAX-6800
   1G/24GB («ASER50XX can update»).
2. Запусти `winflash.CMD` от администратора. Это утилита AMI AFU с флагами `/P /B /N /K /X /R`, где `/X`
   отключает проверку ID платы.
3. После перезагрузки в BIOS проверь версию.

Зачем: по отзывам на форуме Beelink, на 5012 видеоядро 7735U перестаёт упираться в 15 Вт. **Риск:**
прошивка BIOS с отключённой проверкой ID — твоя ответственность. Если боишься, пропусти этот шаг: atrium
работает и на заводском BIOS.

## Настройки BIOS

**Del** при включении — BIOS, **F7** — меню загрузки. Остальное — по умолчанию.

| Настройка | Значение | Зачем |
|---|---|---|
| ACPI: Hibernation, Sleep | выкл. | сна нет никогда: бокс работает как сервер |
| PCIe ASPM (все 4 порта) | Disabled | линии PCIe не засыпают: нет подвисаний NVMe и сети, нет задержек на пробуждение |
| NB Azalia (HDMI/DP-звук) | Disabled | звук только через USB-ЦАП |
| Wake On Voice | Disabled | не нужен |
| Network Stack, LAN PXE ROM | Disabled | сетевая загрузка не нужна, загрузка быстрее |
| fTPM | Route to SPI TPM, Security Device Support: Disable | TPM медиацентру не нужен |
| UMA Frame Buffer Size | **4G** | видеопамять для эмуляторов вплоть до PS3 |
| FCH → Ac Power Loss Options | Always On | после отключения света бокс включается сам |
| Quiet Boot | Disabled | видно сообщения при загрузке |
| Setup Prompt Timeout | 5 | успеть нажать Del |
| Secure Boot | выкл. (как пришло) | не нужен. Включить можно только здесь, в BIOS; ключи Microsoft UEFI CA 2011/2023 уже в базе, загрузчик Fedora с ним загрузится |

Встроенный аналоговый звук (`1022:15e3`) в BIOS не выключается: в пункте Audio IOs нет варианта
Disabled. Его прячет параметр ядра `pci-stub.ids=1022:15e3` (установка, шаг 12).

## Вывод на ТВ

ТВ подключён к **штатному HDMI бокса** пассивным кабелем Ultra High Speed (48G): 3840×2160 при 120 Гц,
RGB 4:4:4, 10 бит, HDR, без сжатия. В паспорте Beelink этот порт значится как HDMI 2.0, но видеоядро
умеет HDMI 2.1 (FRL), и порт его пропускает. В Linux FRL для amdgpu есть с ядра 7.2, но выключен по
умолчанию. Включает его параметр ядра `amdgpu.dcfeaturemask=0x402` (установка, шаг 12). Без параметра
HDMI работает как 2.0: 4K 60 Гц в RGB 8 бит или 4K 120 Гц только в YCbCr 4:2:0.

Активные кабели DisplayPort → HDMI 2.1 не нужны. Как мы месяц с ними мучились, где была правда, как
проверить, что идёт HDMI 2.1, и запасной путь с активным кабелем (вместе с прошивкой Chrontel CH7218) —
в [tv-output.md](tv-output.md).

CEC на штатном HDMI бокса в Linux нет: раньше его делал чип в активном кабеле.

У ТВ в ходу два входа — бокс и PS5. Когда ТВ подолгу стоит на PS5, он перестаёт отвечать на входе бокса,
и без присмотра бокс терял единственный экран (RDP не подключался). Поэтому у нас выход всегда считается
подключённым, а описание экрана ядро берёт из файла, снятого с ТВ: `atrium-hdmi-keep`
([установка, шаг 19](install.md)). Если у ТВ один активный вход — не нужно.

## ТВ LG OLED C3

| Настройка | Значение | Зачем |
|---|---|---|
| Вход | любой HDMI (у нас HDMI 4) | у C3 все четыре HDMI 2.1 с 4K 120 Гц; eARC — HDMI 2 |
| HDMI Ultra HD Deep Colour | вкл. для этого входа | иначе ТВ не примет 4K 120 Гц с полным цветом |
| Формат кадра | «Исходный» | пиксель в пиксель, отдельного Just Scan в webOS 23 нет |
| **Сдвиг экрана** (Уход за OLED) | **выкл.** | он сдвигает картинку на несколько пикселей, слева пропадала полоска 4 px |
| Значок входа «ПК» | не ставим | мы с ним не сравнивали |
| SIMPLINK (CEC) | по желанию | нужен PS5 и другим устройствам; у штатного HDMI atrium CEC нет |
| Яркость, режим картинки | на вкус | для SDR хорош FILMMAKER MODE |

OLED защищают так: через 15 минут простоя включается заставка, через 30 минут экран гаснет, плюс
автовыключение самого ТВ.

Проверить, режет ли ТВ края: `src/wallpaper/make_edge_test.py` делает тест-обои с полосками толщиной
1–16 px у каждого края.

## Звук

- USB-ЦАП (у нас SMSL, UAC2) — **единственная** звуковая карта в системе. HDMI-звук выключен в BIOS,
  встроенный аналоговый спрятан через `pci-stub`.
- PipeWire работает на 48 кГц. Когда играет один поток, ЦАП переключается на частоту файла
  (44,1–192 кГц), без пересчёта (`/etc/pipewire/pipewire.conf.d/50-atrium-rates.conf`).
- Проверить частоту во время воспроизведения: `cat /proc/asound/card0/pcm0p/sub0/hw_params`.
- Громкость регулируется программно, ручка ЦАПа стоит в одном положении. Сквозной вывод Dolby/DTS в
  плеерах выключен: ЦАП стерео.

## Диски

**Системный Crucial P3 Plus.** Прошивка P9CR411 — сборка для Beelink. Сервер Crucial отвечает «no updates
available», а публичная последняя (P9CR40D) старше. Обновлять нечем и незачем.

### Прошивка WD Blue SN5000

WD официально обновляет диски только из Windows (WD Dashboard). Но файлы прошивок лежат на их сервере, и
`nvme-cli` ставит их на Linux. У нас было **291020WD**, стало **291050WD** — последняя для SN5000
500 ГБ/1 ТБ/2 ТБ, от 13.03.2026.

Файл прошивки описан в `https://wddashboarddownloads.wdc.com/wdDashboard/firmware/WD_Blue_SN5000_2TB/291050WD/device_properties.xml`:
- режим установки mode3;
- ставится поверх 291000WD, 291010WD или 291020WD.

**Сертификат сервера WD истёк 27.11.2025**, поэтому скачиваем с проверкой по отпечатку ключа сервера, а
не по сертификату. Если WD обновит сертификат, качай обычным `curl` без `-k`.

```bash
dnf -y install nvme-cli && mkdir -p /root/dist && cd /root/dist && curl -fsS -k --pinnedpubkey 'sha256//o7rO/T+OE4eHjYAaM71w35gNKlfT/dX4QzgZDDRDhxA=' -o 291050WD.fluf https://wddashboarddownloads.wdc.com/wdDashboard/firmware/WD_Blue_SN5000_2TB/291050WD/291050WD.fluf && echo "6c45aeb16cee701e03d286adf9ce9a7ccfc89b2fc13678733e990d30b7fba44b  291050WD.fluf" | sha256sum -c
```

Прошивка. Команда сама находит диск по модели и останавливается, если версия не 291020WD или диск
смонтирован:

```bash
D=$(for c in /sys/class/nvme/nvme*; do [ "$(xargs < $c/model)" = "WD Blue SN5000 2TB" ] && echo /dev/${c##*/}; done); echo "WD = $D"; [ -n "$D" ] && [ "$(xargs < /sys/class/nvme/${D##*/}/firmware_rev)" = "291020WD" ] && ! grep -q "^${D}n1" /proc/mounts && cd /root/dist && nvme fw-download $D --fw=291050WD.fluf && { nvme fw-commit $D --slot=2 --action=3; sleep 3; nvme fw-log $D; nvme id-ctrl $D | grep -E "^(mn|fr) "; }
```

После этого перезагрузись: ядро пишет «controller capabilities changed, reset may be required». Старую
прошивку в слоте 1 диск стирает, отката нет.
