# Стрим игр с ПК: Apollo → Moonlight, Steam Link и сеть

[English version](../en/streaming.md) · [Установка](install.md) · [Железо](hardware.md) · [Известные проблемы](problems.md) · [Вывод на ТВ](tv-output.md)

## Коротко

- На игровом ПК (Windows, NVIDIA RTX 40) работает **Apollo** — сервер стрима. На atrium — **Moonlight**,
  клиент.
- Поток: **3840×2160 при 120 к/с, AV1, 150 Мбит/с**, декодирует видеокарта бокса. ТВ работает на 120 Гц,
  и поток совпадает с ним кадр в кадр.
- **Steam Link** — второй вариант, для игр из Steam.
- Плавность решает **сеть**: проводной путь без перепадов скорости (2,5 → 1 Гбит/с) и очереди коммутаторов,
  которые не теряют пачки пакетов. Что мы поправили на MikroTik — ниже.

## Сервер: Apollo на ПК с Windows

**Что это.** Apollo — форк Sunshine, открытого сервера стрима игр, с которым работает Moonlight. Главное его
дополнение — **виртуальный экран** (SudoVDA): на каждый стрим Apollo создаёт виртуальный монитор с
разрешением и частотой клиента, 3840×2160 при 120 Гц. Настоящий 4K-монитор на 120 Гц ПК не нужен, а
настоящие мониторы могут быть выключены.

**Установка.** Установщик для Windows — в релизах Apollo на GitHub (ClassicOldSong/Apollo). Веб-интерфейс —
`https://localhost:47990` на ПК (самоподписанный сертификат), при первом запуске задай там логин.
Установщик сам открывает порты в фаерволе Windows: TCP 47984, 47989, 48010 и UDP 47998–48000, 48002, 48010.
Порт веб-интерфейса 47990 — для самого ПК.

**Сопряжение.** Moonlight находит ПК в локальной сети сам (mDNS) или по IP и показывает PIN. Введи его в
веб-интерфейсе Apollo, вкладка PIN.

**Наши настройки:**
- **Кодировщик:** NVENC на видеокарте ПК, кодек AV1 (у RTX 40 есть кодировщик AV1).
- **Виртуальный экран:** «Headless Mode» вкл., «Move the Virtual Display to the bottom right» вкл. Во время
  первого стрима сделай виртуальный экран основным в «Параметры Windows → Дисплей»: Windows запоминает
  раскладку для этого экрана.
- **Приложения:** Desktop и Steam Big Picture.
- **Command Preparations, Undo.** После стрима Windows забывает обои каждого монитора: поменялся набор
  мониторов. Их возвращает `src/pc/apollo-wallpapers.ps1`:
  1. один раз, пока обои правильные: `powershell -ExecutionPolicy Bypass -File <путь>\apollo-wallpapers.ps1 save`;
  2. в Apollo, команда Undo: `powershell -NoProfile -ExecutionPolicy Bypass -File "<путь>\apollo-wallpapers.ps1" restore`.
     Она сразу возвращает управление, а копия в фоне ждёт, пока уйдёт виртуальный экран, и ставит обои.
- **Завершить стрим с клавиатуры ПК:** `src/pc/apollo-stop.ps1`. Один раз:
  `powershell -ExecutionPolicy Bypass -File <путь>\apollo-stop.ps1 setup` — спросит логин веб-интерфейса
  Apollo, сохранит его зашифрованным только для этого пользователя Windows (DPAPI, `apollo-cred.xml` рядом
  со скриптом — в git не класть) и создаст ярлык в «Пуске» с клавишами **Ctrl+Alt+End**. По ним скрипт входит в
  веб-API и закрывает запущенное приложение. После отключения клиента Apollo держит сеанс ещё секунд 90,
  поэтому завершай стрим через Quit в Moonlight или этими клавишами.

## Клиент: Moonlight на atrium

Ставится на шаге 15 установки (Flathub `com.moonlight_stream.Moonlight`), значок в доке.

| Настройка | Значение | Зачем |
|---|---|---|
| Разрешение | 3840×2160 | родное для ТВ |
| Частота кадров | **120 к/с** | ТВ работает на 120 Гц: один кадр потока на одно обновление, без рывков |
| Битрейт | 150 Мбит/с | с запасом для 4K 120 в AV1; малая доля гигабита |
| Кодек | AV1 | лучшее качество на бит; Radeon 680M декодирует его аппаратно |
| Декодер | аппаратный (VA-API) | процессор свободен; в панели VCN показывает загрузку декодера |
| V-Sync | выкл. | минимальная задержка |
| Frame pacing | выкл. | минимальная задержка; включи, если кадры идут неровно |
| HDR | выкл. | рабочий стол в SDR |
| YUV 4:4:4 | выкл. | для игр не нужен, а полосу ест |
| Режим окна | на весь экран | |

Moonlight хранит это в `~/.var/app/com.moonlight_stream.Moonlight/config/Moonlight Game Streaming Project/Moonlight.conf`
пользователя ТВ. Во время стрима **Ctrl+Alt+Shift+S** показывает статистику: декодер, время кадра, пропуски,
задержку сети. **Ctrl+Alt+Shift+Q** — выйти из стрима.

Для Moonlight в фаерволе atrium ничего открывать не нужно: клиент подключается сам.

## Steam Link

Flathub `com.valvesoftware.SteamLink` (шаг 15), сопрягается со Steam на ПК, декодирует через VA-API. На
шаге 15 же открывается служба фаервола `steam-streaming` для локальной сети. Журнал —
`~/.var/app/com.valvesoftware.SteamLink/data/Valve Corporation/SteamLink/streaming_client.log` у пользователя
ТВ: «Got video sequence N, expected N-1, sending lost data notification» значит, что пакеты теряются.

## Сеть: почему стрим дёргался и что помогло

**Признак.** Steam Link дёргался каждые 1–3 секунды, Moonlight показывал пропуски кадров. В журнале — сплошные
«lost data notification».

1. **Буфер приёма UDP на atrium.** Рос счётчик `RcvbufErrors` (`nstat -az UdpRcvbufErrors`).
   `/etc/sysctl.d/90-atrium-stream.conf` поднимает `net.core.rmem_default/rmem_max` до 16 МБ (шаг 15).
   Счётчик встал, но пакеты всё равно терялись. Steam Link ставит буфер своему сокету сам, так что для него
   эта настройка — только запас.
2. **Перепад скорости на пути.** ПК был подключён к порту 2,5 Гбит/с, а дальше путь до atrium шёл на
   1 Гбит/с. ПК отправляет каждый кадр пачкой на 2,5 Гбит/с, и очередь первого порта на 1 Гбит/с
   переполняется. На MikroTik это счётчик `tx-queue-drop` этого порта (`/interface ethernet print stats`) —
   там были тысячи. **Решение:** ПК переключён в порт на 1 Гбит/с, весь путь на одной скорости.
3. **Короткие очереди на MikroTik.** По умолчанию порты MikroTik работают только с маленькой аппаратной
   очередью (`only-hardware-queue`), и пачки изредка всё равно терялись (раз в 30–60 секунд). **Решение:**
   программная очередь FIFO на 500 пакетов на всех LAN-портах ethernet каждого MikroTik на пути:

   ```
   /queue type add name=pfifo-500 kind=pfifo pfifo-limit=500
   /queue interface set [find where interface~"ether" and interface!="ether1"] queue=pfifo-500
   ```

   `ether1` — порт WAN на роутере, его не трогаем: на канале 100 Мбит/с 500 пакетов — это до 60 мс очереди.
   На коммутаторах без WAN — на все порты `ether`. Загрузка процессора коммутаторов осталась 1–2 %.
   Проверка: `/queue interface print` и `tx-queue-drop` в `/interface ethernet print stats`. Откат:

   ```
   /queue interface set [find where interface~"ether"] queue=only-hardware-queue
   /queue type remove pfifo-500
   ```

**Рекомендации:**
- оба конца на кабеле, Wi-Fi только запасной;
- одна скорость на всём пути, а на перепаде — коммутатор с большим общим буфером (например, MikroTik CRS)
  вместо маленьких коммутаторов с буфером в сотни килобайт;
- сам битрейт не проблема: 150 Мбит/с — это 15 % гигабита; проблема — пачки.
